# Качество обращений NYC 311

## 1. Контекст и входные данные

Вопрос Project Brief касается числа обращений и медианного времени до закрытия по типам проблем и агентствам в Манхэттене за январь 2025 года.
Одна строка представляет обращение, бизнес-ключ `unique_key`

Входной файл из ЛР № 2

```text
s3://raw/nyc311_manhattan/ingested_on=2026-10-14/nyc311_manhattan_2025-01.csv
```

## 2. Профиль

В raw 61 331 строка и 8 полей.
Для каждого из пяти выбранных полей проверены все 61 331 строки, пропуском считается NULL или пустой текст после удаления краевых пробелов.
Типы в таблице определены автоматическим чтением DuckDB

| Поле | Тип DuckDB | Пример | Пропуски | Доля, % |
|---|---|---|---:|---:|
| `unique_key` | BIGINT | `63572326` | 0 | 0 |
| `created_date` | TIMESTAMP | `2025-01-01T00:00:37.000` | 0 | 0 |
| `closed_date` | TIMESTAMP | `2025-01-01T00:07:59.000` | 1 036 | 1,6892 |
| `complaint_type` | VARCHAR | `AHV Inspection Unit` | 0 | 0 |
| `agency` | VARCHAR | `DCWP` | 0 | 0 |

Непустых уникальных ключей 61 331, избыточных повторов 0.
Повторы посчитаны суммой `число строк ключа − 1` по непустым ключам после удаления краевых пробелов.
Период создания от `2025-01-01 00:00:37` до `2025-01-31 23:59:48`

| Агентство | Обращения | Доля, % |
|---|---:|---:|
| HPD | 24 333 | 39,6749 |
| NYPD | 17 656 | 28,7881 |
| DSNY | 4 642 | 7,5688 |
| DEP | 3 239 | 5,2812 |
| DOT | 2 839 | 4,6290 |
| Остальные | 8 622 | 14,0581 |

У 1 036 обращений нет даты закрытия, они остаются в наборе, но не подходят для расчёта времени до закрытия.
HPD содержит 39,6749% записей, поэтому будущие сравнения должны учитывать разный размер групп

## 3. Правила и результаты

Условия, критичность и связь с задачей описаны в [разделе правил ноутбука](../notebooks/profile_quality.ipynb#Правила-качества).
Все пороги заданы числом нарушений и используются в коде

| id | Проверено | Нарушения | Доля, % | Порог, строк | Превышен | Действие |
|---|---:|---:|---:|---:|---|---|
| `unique_request_key` | 61 331 | 0 | 0 | 0 | нет | quarantine |
| `created_in_period` | 61 331 | 0 | 0 | 0 | нет | quarantine |
| `complaint_type_present` | 61 331 | 0 | 0 | 0 | нет | flag |
| `agency_present` | 61 331 | 0 | 0 | 0 | нет | flag |
| `valid_closure_order` | 60 295 | 27 | 0,0448 | 0 | да | quarantine |

Для порядка дат проверены только строки с непустой датой закрытия и распознанной датой создания.
Например, обращение `63656893` создано `2025-01-06T07:51:00.000`, но закрыто `2025-01-04T02:00:00.000`.
Такие 27 записей перенесены в карантин, даты не исправлялись

## 4. Подготовленные данные

```text
s3://staging/nyc311_manhattan/source_ingested_on=2026-10-14/staging.parquet
s3://staging/nyc311_manhattan/source_ingested_on=2026-10-14/quarantine.parquet
```

Баланс сохранён, `61 331 = 61 304 + 27`.
В staging идентификатор оставлен текстом, даты явно приведены к TIMESTAMP.
У текстовых полей удалены краевые пробелы, пустые значения приведены к NULL, неизвестные значения не восстанавливались

Признаки `quality_missing_complaint_type` и `quality_missing_agency` равны `true` при пропуске соответствующего поля.
В этом снимке оба признака везде `false`, число несовпадений с условиями равно нулю.
На повторно прочитанном staging проверены критические правила, нарушений нет

Карантин сохраняет все 8 исходных полей без нормализации.
`quality_rule_ids` содержит список строк VARCHAR[], `quarantine_reason` перечисляет причины через `; `.
Каждая исключённая строка сохранена один раз со всеми критическими причинами.
Исходные значения и причины сверены после чтения из S3, расхождений нет.
Подсчёты по staging будут меньше raw на 27 обращений, это следствие исключения противоречивых записей

## 5. Воспроизводимость и ограничения

В [notebooks/profile_quality.ipynb](../notebooks/profile_quality.ipynb) сохранены запросы и актуальные выводы.
Проверены два полных выполнения сверху вниз с отдельными чистыми ядрами Jupyter

| Выполнение | raw | staging | Карантин |
|---|---:|---:|---:|
| Первое | 61 331 | 61 304 | 27 |
| Повторное | 61 331 | 61 304 | 27 |

Оба результата прочитаны напрямую из S3, повтор перезаписывает те же два ключа.
SHA256, ETag, размер и LastModified raw совпали до и после обработки

Источник динамический, результаты относятся к снимку ЛР № 2, а дата закрытия не доказывает качество решения проблемы.
Восемь выбранных полей не позволяют выполнить срез по community board из полного Project Brief
