# Витрина обращений NYC 311

## Модель

Выбран основной вопрос Project Brief

> Как различались число обращений и медианное время до закрытия по типам проблем и ответственным агентствам в Манхэттене в январе 2025 года?

Одна строка `service_requests` представляет одно обращение из staging ЛР № 3. Естественный ключ `unique_key` сохраняется без изменений. Выбрана одна широкая таблица, поскольку агентство и тип проблемы уже присутствуют в каждой записи и для этого вопроса отдельные измерения не требуются.

- `request_count` равен 1 обращению. Его сумма по непересекающимся группам агентств, типов проблем и периодов создания даёт число обращений, как и `COUNT(*)`.
- `resolution_hours` хранит время до закрытия в часах. Для будущего показателя берётся медиана заполненных значений внутри группы. Часы не суммируются для ответа на этот вопрос, медианы разных групп не складываются и не усредняются.

Вход и результат

```text
s3://staging/nyc311_manhattan/source_ingested_on=2026-10-14/staging.parquet
s3://mart/nyc311_manhattan/source_ingested_on=2026-10-14/service_requests.parquet
```

`created_date` и `closed_date` описывают события в источнике без добавленного часового пояса. Сырой снимок собран 2026-10-14, дата указана в manifest ЛР № 2. `source_ingested_on=2026-10-14` является логической датой загрузки Airflow и не заменяет время события.

## Сопоставление полей

| Поле витрины | Источник в staging | Преобразование | Смысл и ограничение |
|---|---|---|---|
| `unique_key` | `unique_key` | Без изменений | Текстовый бизнес-ключ обращения |
| `created_date` | `created_date` | Без изменений | TIMESTAMP создания, определяет период обращения |
| `closed_date` | `closed_date` | Без изменений | TIMESTAMP закрытия, NULL допустим |
| `complaint_type` | `complaint_type` | Без изменений | Тип проблемы, пропуск сохраняется с флагом |
| `agency` | `agency` | Без изменений | Агентство, пропуск сохраняется с флагом |
| `request_count` | Строка staging | Константа `1::INTEGER` | Одно обращение, аддитивная мера |
| `resolution_hours` | `created_date`, `closed_date` | Разность в микросекундах делится на 3 600 000 000 | DOUBLE, часы до закрытия, NULL при отсутствии даты |
| `quality_missing_complaint_type` | `quality_missing_complaint_type` | Без изменений | BOOLEAN, true при отсутствии типа проблемы |
| `quality_missing_agency` | `quality_missing_agency` | Без изменений | BOOLEAN, true при отсутствии агентства |

## Проверки и ограничения

Конкретные SQL-запросы и результаты находятся в [разделе проверок ноутбука](../notebooks/build_mart.ipynb#Проверки-сохранённой-витрины).

Из S3 повторно прочитаны 61 304 строки и 9 полей. Гранулярность и число строк совпали со staging, дополнительных исключений нет. Пропусков и повторов ключа нет, имена и типы всех полей проверены. Счётчик заполнен и равен 1, рассчитанное время совпадает с разностью исходных дат и неотрицательно. У 1 036 записей время осталось NULL, как и дата закрытия в staging.

Исходные значения и оба флага сверены построчно с учётом повторов, расхождений нет. В текущем снимке установленных флагов нет ни в staging, ни в mart. Короткая группировка подтвердила доступность срезов по агентству и типу проблемы. Два выполнения с чистыми ядрами дали одинаковые количества строк и SHA256 выходного Parquet, входной staging не изменился. Повтор перезаписывает тот же объект.

Витрина содержит допустимые записи staging, поэтому в её подсчёты не входят 27 обращений, перенесённых в карантин в ЛР № 3. Обращения без даты закрытия учитываются в числе обращений, но не в медиане времени. Закрытие может быть позже января 2025 года, верхняя граница длительности искусственно не ограничивается. Выводы относятся к динамическому снимку, а дата закрытия не доказывает фактического решения проблемы.
